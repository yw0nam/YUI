mocks/character-window · #2007

A failed turn shows its next step

Each failure keeps its condition text as it is today and gains one action, in the inline-link treatment the existing Connect fix already wears. The client writes no line for the character. Frames are at real size: character window 400 × 600, message window 340 wide, settings window 760 × 680.

1. Key rejected (401 or 403) in the input

The typed message is already back in the field (a turn that fails before any reply restores it). After: Change key opens Settings › Connection on the Key rejected state of part 2, with the key field focused.

2. Quick start once connected (Settings › Connection)

Today the connected state hides the key field and says Connected whatever the last call returned. After (A): a Key row with Replace key always sits under the done line; click it to open the paste row. After (B): a 401 or 403 swaps the done line for the rejected line and opens the key rows, until a call succeeds.

3. Mic blocked on the status pill

Top 150px of the 400 × 600 character window. After: Open mic settings opens the macOS microphone privacy pane (System Settings › Privacy & Security › Microphone). The condition text stays.

4. Network drop or stall in the input

Today a typed turn that fails puts its text back into the open, empty field (quoted-turn.ts failed() calls restoreInput), so the field below already holds it in both frames. After: Retry sends that restored text again, one click in place of Enter; the dispatcher has no resend of its own. A voice turn keeps no text, so it gets no Retry. A 429 (usage limit) and a non-auth 4xx keep their line with no action, because retrying at once cannot succeed; they are not drawn as changed.

5. A typed turn fails after the input was closed (Journey 4)

Not decided. Today nothing shows, and the typed text is lost (the field is closed, so it is not restored). Two options for the owner.
