# UI i18n (ja / en / ko) — Design

## Goal

Localize YUI's client UI into Japanese, English, and Korean. UI text only — not
character speech, user input, or backend payloads. The character keeps speaking
Japanese via TTS; this is purely the surrounding app chrome (settings panel,
controls, chat surface labels, indicators).

## Decisions

- **Languages:** `en`, `ja`, `ko`.
- **Fallback / source key language:** `en`. Missing translation → English string.
- **Selection:** manual picker in the settings panel; choice persisted in
  `localStorage`. App always starts in `en`; user switches once and it sticks.
- **Scope:** entire UI in one pass.
- **Switch mechanism:** `t(key)` everywhere + host re-mount on change (approach A
  below).
- **ja content:** authored by sub-agents from the en/ko source.

## Architecture

### `src/ui/i18n.ts` (one new module)

- `export type Locale = "en" | "ja" | "ko"` — `DEFAULT_LOCALE = "en"`.
- Locale persisted via the existing `persisted-store` pattern (same as other
  `*-settings.ts`). `getLocale()` / `setLocale(l)`.
- `t(key)` lookup: `dict[locale][key] ?? dict.en[key] ?? key`. Same shape as the
  current `tool-labels.ts` lookup, which folds into this module.
- `subscribe(fn)` → called on `setLocale`, returns an unsubscribe. Hosts use it to
  re-mount.

### Dictionaries — `src/ui/i18n/{en,ja,ko}.ts`

- Flat `Record<string, string>` keyed by semantic id, grouped by prefix:
  `endpoints.*`, `errors.*`, `speaker.*`, `tabs.*`, `aria.*`, etc.
- `en` is the source of truth for the key set (authored first).
- `ko` receives the existing Korean strings (moved out of the components).
- `ja` authored by sub-agents.

### Extraction

Replace the ~138 inline Korean string literals with `t("…")` across:
`quick-controls.ts`, `surfaces.ts`, `cue-list.ts`, `voice-input-indicator.ts`,
`voice-input-status.ts`, `capture-indicator.ts`, `main.ts`, `settings-main.ts`.
Covers `textContent`, `placeholder`, `title`, `aria-label`, inline HTML template
text, and runtime-built error/status strings.

`tool-labels.ts` drops its private `TOOL_LABELS` locale map and delegates lookup
to `i18n` (keys become `tool.<id>`).

### Language picker

3-way segmented control (日本語 / English / 한국어) in the settings panel, reusing
the existing `yui-seg` radiogroup pattern (as used for filler-language). On
change → `setLocale(l)`.

### Switch wiring

The **host** owns re-mount, not the component (avoids the picker destroying its
own DOM mid-click):

- `settings-main.ts` and `main.ts` subscribe to locale changes; on change they
  `dispose()` the current quick-controls / surfaces and recreate them.
- Re-mount deferred to a microtask/rAF so the triggering click handler unwinds
  first.
- Transient state (which tab is open, scroll position) resets on switch. Accepted
  — language switches are rare. (YAGNI: no state preservation.)

## Data flow

```
user clicks picker → setLocale("ja") → persist + notify subscribers
   → host dispose() + recreate (deferred) → templates call t() → ja strings render
```

## Testing (TDD — failing test first per AGENTS.md)

- `i18n.test.ts` — lookup hits locale; missing key falls back en→key; `setLocale`
  persists and notifies subscribers.
- key-completeness test — every `en` key exists in `ja` and `ko` (catches missing
  translations in CI; this is the guard that keeps the dicts honest).
- picker test — clicking a language calls `setLocale` and triggers host re-mount.

## Out of scope

- Character speech / subtitle translation.
- User-input translation.
- RTL languages, number/date formatting, pluralization (no current need).

## Delegation

- **Software Architect** — `i18n.ts` + dictionary structure + completeness test.
- **Frontend Developer / UI Designer** — string extraction + picker + host wiring.
- **ja translation** — fan out per surface from the en source.
