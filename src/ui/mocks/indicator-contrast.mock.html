YUI — indicator contrast & error-token mock

Standalone visual-approval harness for the doctrine bundle: chip/pill scrim contrast on any backdrop (R3 + H2), the input row's inline error color token (R1), and the voice-indicator "fired" dot variants (R2). Every pair below is shown over three representative desktop backdrops — pure white, a busy light surface, and near-black — because the point of the bundle is the Legible-on-Anything rule: a surface's own self-contrast should carry it regardless of what's underneath.

[R3 + H2] Chip / pill surface contrast

--yui-text-dim on the 64%-alpha --yui-scrim measures ~2.65:1 against white — under the guideline for small label text; the 82%-alpha --yui-scrim-strong raises it to ~4.1:1. Alongside the opacity bump, backdrop blur is removed entirely (the frosted backdrop is reserved for the speech bubble only — the bubble-only rule); the extra opacity compensates so the pill still separates cleanly from a busy backdrop without borrowing blur.

[R1] Input-row inline error

The current inline error borrows --yui-accent (hue 75), the same hue as every warm "moment" in the system (focus, speech onset) — a failed send reads as one more warm accent, not as wrong. --yui-danger (hue 35) is deliberately hue-separated from Hearth Amber so an error can never be mistaken for a warmth moment, while keeping the same lightness and the no-side-stripe, text-color-only treatment.

[R2] Voice-indicator "fired" dot

The current error dot (oklch(0.68 0.13 28)) is an off-token red that collides in meaning with Ember Red without being it; both variants below replace it with the canonical --yui-danger. For the fired state, Variant A formalizes a standalone green success hue (145°); Variant B keeps the fired moment inside the amber family — a steady, non-pulsing accent dot — so "sent" still reads as a warmth moment rather than importing a foreign hue. Both are built on the R3 after-state (scrim-strong, no blur) chip.
